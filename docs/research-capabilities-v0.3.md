# 六组研究能力：独立产品开发与验收规格

规划日期：2026-10-14。实现版本：0.3.0。实际 API 见 research-v0.3.md，验证结果见 verification-v0.3.md。本文件保留研究目标及实现路线。

## 1. 交付范围

- 完成独立jsPsych插件、独立配置器、通用服务器代理、研究示例、数据字典和测试。
- 运行时继续锁定jsPsych 7.3.4，保留九类插件及现有ESM、浏览器script入口。
- 配置器按六个研究方向组织入口；每组提供完整参数面板、可运行预览和代码导出。
- 跨日随访、多次访问、参与者返回链接和纵向收集由编辑器的实验管理负责。插件提供当次试次的数据、会话上下文和可注入的数据回调。
- 语音采用MiniMax服务。OpenAI与火山的实时语音文档用于比较会话、打断和时间记录方式。

## 2. 当前实现与补齐目标

| 研究方向 | 当前基础 | 本轮补齐 |
| --- | --- | --- |
| 判断与建议采纳 | 数值初始判断、信心、固定或生成建议、最终判断、WOA | 证据查看与核查任务；建议质量、解释、身份和帮助时机；数值与类别判断 |
| 学习与认知卸载 | 辅导对话、撤除AI后的迁移表单 | 答案、逐步提示、苏格拉底三种策略；前测、练习、主动求助、即时独立测验与迁移 |
| 创造与共同创作 | AI起稿、稿件编辑、完整稿件替换、多方案单选 | 人先写、AI先写、轮流修改；显式接受或拒绝建议；草稿、修改、撤销和方案比较 |
| 访谈与自适应提问 | 通用访谈指令、多轮聊天、固定或生成问卷 | 必问主题、问题提纲、追问范围与次数、停止规则；题库选题和即时生成分别实现 |
| 角色与多代理 | 角色配置、固定或随机顺序、共享对话讨论 | 独立作答、讨论、最终判断三个阶段；独立阶段历史隔离、明确分歧、共识与保留意见 |
| 多模态 | 图片和音频附件、录音、媒体呈现 | 图片实际加载计时；转录、转录修正、连续播报、插话打断；媒体和语音时间记录 |

### 判断与建议采纳

- 默认流程：初始判断和信心 → 获取建议 → 证据查看或核查 → 最终判断和信心。帮助时机支持初始作答后、主动请求、研究者设定的等待时点。
- 建议内容、解释、来源身份分别配置。固定材料用于需要精确控制建议质量的研究；实时生成记录目标质量及可核验的实际质量。
- 证据采用研究者提供的材料、来源标识和可选链接；保存打开、切换、核查回答与可见时长。点击事件只代表查看操作。
- 数值任务保留WOA和误差；分母为零返回null，比例保持原值。类别任务记录修订与采纳，WOA为null。

### 学习与认知卸载

- 三种辅导策略作为显式配置，记录实际提示、提示层级、主动求助和答案揭示。
- 独立测验与迁移阶段关闭AI生成入口及历史提示，针对这些阶段验证AI请求数为0。
- 正确答案、评分规则由研究者提供；开放回答保留原文，可在 jsPsych 原生 on_finish 中评分。模型生成题目保留生成来源。
- 同一次实验的延迟测验示例使用原生jsPsych timeline插入休息或其他任务，再呈现测验。插件不承担跨日调度。

### 创造与共同创作

- 起稿方式支持参与者、AI、研究者固定草稿；轮流修改由明确的阶段和轮数控制。
- AI修改建议先作为候选显示，接受、拒绝、部分采纳分别记录。整稿替换保留为可选方式。
- 编辑过程记录插入、删除、替换、撤销与时间；在阶段提交和稿件结束时保存完整快照。每次失去焦点不能成为唯一的修订记录来源。
- 多方案支持选择、排序与评价；记录方案标识、实际呈现顺序和查看过程。创造性评分规则由研究者提供。

### 访谈与自适应提问

- 固定题库模式只呈现题库内的题目；支持固定顺序和研究者规则选题。模型选题时只接受合法题目ID。
- 即时生成模式返回结构化问题、主题ID和追问类型；客户端检查允许主题、轮数和重复问题。
- 必问主题逐一呈现并获得有效回答；自动停止需满足必问条件与研究者停止规则。参与者主动结束另记原因。
- 保存实际问题、回答、选题依据、追问父问题、跳过原因、主题覆盖和停止原因。

### 角色与多代理

- 独立阶段仅提供共同材料和各角色自身历史，锁定各自答案后开启讨论。
- 讨论阶段按固定、种子随机或研究者指定顺序发言；记录实际顺序、角色身份、实际模型与可见上下文。
- 结束阶段保留各角色最终立场及参与者判断；共识、分歧和少数意见分别记录。
- 意见分歧可使用固定立场材料或角色指令。保存实际观点，避免仅依据条件标签推断模型形成了目标分歧。

## 3. 共享接口与数据

- `createAITrial(mode, options)`继续作为主要入口。新增可序列化的`research`任务配置和`speech`语音配置，按所选插件验证可用字段；未配置时沿用旧行为。
- 新增`createSpeechClient`和`createSpeechProxyTransport`。`speech_client`作为运行时引用注入，复用现有client/session的动态参数保护方式；配置导出保留连接选择与参数。
- 任务配置分为建议、学习、共创、访谈、多代理、多模态六组。配置器从同一份字段定义读取默认值、选项、说明和验证约束。
- 各组共用阶段状态、请求取消、错误处理与事件记录。阶段转换由代码约束；必答、轮数、独立作答和停止规则在客户端检查。
- 保留现有`AIResearchData.v1`字段，新增`research_group`、冻结任务配置、`phases`、`speech_turns`、`speech_playback`、`media`。事件使用相对试次开始的毫秒数，并关联阶段、问题、稿件、代理或语音轮次。
- 分别记录参与者作答、模型请求、转录、播报生成、实际播放、暂停和排队时间；浏览器隐藏与重新可见产生事件。
- `AIExperimentConfig.v1`保留已有参数形状，配置导入检查精确版本。研究者通过 createConfiguration 明确创建 0.3 副本；迁移界面另行开发。
- 新功能沿用实时、预生成、固定回放和配对回放。材料不足按声明的错误策略处理，实际调用与实际呈现均保留。
- 旧模块导出器纳入兼容回归；独立包从同一源码生成专用入口构建，将源码和样式共同压缩，以满足100000字符限制。

## 4. MiniMax语音路线

### 已核实的接口

- ASR：`asr-1.0`，国内接口`https://api.minimax.cn/v1/speech_to_text`，使用multipart音频文件；支持JSON或SSE返回。
- ASR当前输入为完整音频片段。官方文档明确列出音频流式输入限制；SSE表示识别结果分段返回。
- TTS：`speech-2.8-turbo`，国内接口`wss://api.minimax.cn/ws/v1/t2a_v2_bidi`；支持流式文本、音频分块、`task_cancel`打断和`task_flush`发送尾句。
- 文本模型继续使用研究者选定的现有连接，地区、模型、账户与思考设置均显式记录。

### 实现方式

- 浏览器连续收音，通过语音活动检测切出完整话段；使用单声道16kHz WAV上传。默认静音判停600ms、最短语音300ms、保留开头200ms、最长话段20秒，研究者可调整。提供按键说话模式。
- 收到转录后提交现有文本模型；模型正文增量直接传入MiniMax双向流式TTS，每轮正文结束发送`task_flush`。
- 用户插话时立即清空本地播放队列，取消旧文本请求，发送`task_cancel`。语音轮次关联音频与文本，迟到数据保持隔离。
- 默认确认转录后提交；研究者可关闭 review_transcript 自动提交。参与者修改转录时保留原文和修订。
- 记录收音起止、判停、ASR请求和结果、正文首字、TTS首包、浏览器播放起止及打断动作。只取得音频时间偏移时记录偏移，逐字已听内容保持未知。厂商取消确认时间保留在接口调查报告中。
- 通用代理新增语音转录HTTP入口和播报WebSocket入口。语音服务单独配置，使用已验证的国内预设；其他服务通过注入式接口扩展。
- 默认保存转录与媒体元数据；原始录音按研究者开关保存，并通过可注入媒体存储接口返回引用。新语音数据避免在每条事件中复制音频内容。

### 2026-10-14合成样本实测

使用现有MiniMax凭据完成5项检查，报告保存在`artifacts/voice-investigation-20261014/report.json`。

| 检查 | 结果 |
| --- | --- |
| 双向流式TTS | 通过；会话就绪后发文本至首个音频包约698.53ms |
| 厂商取消合成 | 通过；本次取消确认约1047.74ms |
| 打断后同连接继续播报 | 通过 |
| JSON转录 | 通过；1.4745秒合成音频转录约5407.85ms |
| SSE转录 | 通过；首个转录增量约5958.19ms，全部返回约6173.77ms |

这是一组短合成样本，尚未覆盖实体麦克风、浏览器播放和完整语音对话。当前测量显示ASR存在数秒等待；完整对话的短延时目标需要专项验收。播报首包时间不等于参与者说完到听见回答的时间。

官方当前按量价格：ASR每小时2.50元；speech-2.8-turbo每万计费字符2.00元，一个汉字计2个字符。文本模型另计；套餐扣减与账户余额需要按实际连接核对。

## 5. 开发顺序与开放标准

1. 共享阶段、参数定义、数据事件与旧配置兼容。
2. 建议采纳和学习流程；补齐独立测验、证据核查、帮助时机与策略控制。
3. 共创、访谈和多代理；完成版本过程、题库约束与独立阶段历史隔离。
4. 图片与语音；接入ASR/TTS、播放和打断，测量完整链路延迟。
5. 六组配置面板、完整研究示例、安装包与开源文档，按以下证据开放。

### 验收矩阵

- 原有九类插件、18个示例、模拟模式、动态参数、回调、CSV/JSON和官方插件混用回归。
- 每组六组至少一个固定材料完整研究示例和一个真实模型场景；实时、回放及配对材料记录可核对。
- 建议：零分母、负WOA、超额修订、类别采纳、证据未查看、帮助时机、建议质量和实际呈现。
- 学习：三种策略、不同提示层级、撤除后AI请求为0、迁移评分和同次延迟测验顺序。
- 共创：人先写、AI先写、输入未失焦直接结束、撤销、部分采纳、拒绝、方案顺序和草稿恢复。
- 访谈：必问主题遗漏、非法题库ID、重复生成、追问上限、主动结束和模型失败。
- 多代理：独立阶段的消息中没有其他代理答案；固定与随机顺序、失败重试、讨论与最终立场。
- 媒体：图片加载失败、实际显示时间、WAV格式、转录纠错、回声误触发、播报插话、迟到音频和断网恢复。
- 浏览器：Chrome/Edge完整流程，Firefox/Safari针对核心交互和媒体能力验证；支持状态按结果注明。
- 语音：合成音频协议回归后，进行真实麦克风和耳机操作；至少20轮测量整体响应的P50/P95。浏览器主动停止播放以100ms内为目标，厂商确认另行记录；整体延迟提供实测值。
- 文本、图片与语音分别标注验收状态。仅完成附件传递或协议测试的项目保持待完整流程验证。

每组交付可使用的API、可视化设置、最小示例、完整研究示例、数据说明和独立验收记录。
